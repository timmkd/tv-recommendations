## Environment Variables

Required in `.env.local`:
- `TMDB_API_KEY` - The Movie Database API key for show search and metadata
- `TRAKT_CLIENT_ID` - Trakt API client ID for show sync and ratings
- `TRAKT_CLIENT_SECRET` - Trakt API client secret for OAuth
- `TURSO_DATABASE_URL` - Turso database connection URL
- `TURSO_AUTH_TOKEN` - Turso authentication token

Optional:
- `OPENAI_API_KEY` - OpenAI API key for AI-powered recommendations (via `src/lib/openai.ts`)
- `OMDB_API_KEY` - OMDB API key for IMDB ratings (free at omdbapi.com, 1000 requests/day)

## Architecture

This is a Next.js 16 app using the App Router with SQLite database (Drizzle ORM + Turso).

### Data Storage

All data is stored in SQLite database via Drizzle ORM:
- `shows` table - Show metadata, user ratings, notes, predictions (synced with Trakt)
- `episodes` table - Episode watch tracking (future use)
- `settings` table - App configuration, Trakt OAuth tokens
- `streamingServices` table - Available streaming services and subscription status
- `deletedShows` table - Prevent re-import of deleted shows from Trakt

Database access is centralized through `src/lib/db`:
- `src/lib/db/schema.ts` - Table definitions
- `src/lib/db/index.ts` - Database connection

### Key Libraries

- `src/lib/tmdb.ts` - TMDB API client for show search, metadata, and poster images
- `src/lib/openai.ts` - OpenAI integration for AI-powered recommendations
- `src/lib/trakt.ts` - Trakt.tv API for importing watch history and two-way sync
- `src/lib/rottentomatoes.ts` - Rotten Tomatoes scraper for critic scores
- `src/lib/justwatch.ts` - JustWatch API for streaming availability (Australian region)
- `src/lib/db` - Database access via Drizzle ORM

### API Routes

All under `src/app/api/`:
- `/api/shows` - CRUD operations for show library
- `/api/ratings` - Update show ratings
- `/api/settings` - Manage settings and subscriptions
- `/api/recommendations` - Generate AI recommendations
- `/api/tmdb/search` - Proxy for TMDB show search
- `/api/trakt/*` - Trakt sync and streaming availability

### Types

All TypeScript types are in `src/types/index.ts`. Key types: `Show`, `Episode`, `Settings`, `WatchPreference`.
Database types are auto-generated by Drizzle from schema.

## Coding Patterns

### Status/Sync Logic: Default to Least Assuming State

When writing logic that determines show status from external data (Trakt progress, etc.), always default to the **least assuming** state, not the most "complete" one.

**Bad pattern:**
```typescript
let status: ShowStatus = 'completed';  // ❌ Dangerous default
if (progress.completed >= progress.aired) {
  status = 'completed';
} else if (progress.completed > 0) {
  status = 'watching';
}
// If no condition matches, defaults to 'completed' - WRONG!
```

**Good pattern:**
```typescript
let status: ShowStatus;
if (progress.completed >= progress.aired && progress.aired > 0) {
  status = 'completed';  // Only when we have positive evidence
} else if (progress.completed > 0) {
  status = 'watching';
} else {
  status = 'watchlist';  // ✅ Safe default - no evidence of watching
}
```

**Why:** A bug with the bad pattern caused 93 watchlist shows to be incorrectly marked as "completed" because they had no progress data and the default was wrong.

## Trakt Sync

Two-way sync with Trakt is enabled for key user data:

### Push to Trakt (automatic on save)
| Local Field | Trakt Feature | Notes |
|-------------|---------------|-------|
| `rating` | Ratings | Converts 0.5-5★ → 1-10 scale |
| `hidden` | Hidden recommendations | Hides from Trakt suggestions |
| `dropped` | "Dropped" custom list | Auto-created if needed |

### Pull from Trakt
Use `GET /api/trakt/shows?syncFromTrakt=true` to import:
- Ratings (only if no local rating exists)
- Hidden status
- Dropped list membership

### Date Tracking
| Field | Set When |
|-------|----------|
| `ratedAt` | User adds/changes rating |
| `predictionsUpdatedAt` | AI predictions are added/changed |
| `rtFetchedAt` | RT scores fetched |
| `streamingFetchedAt` | Streaming availability fetched |

### Streaming Data Fallbacks
Streaming availability uses 3-layer fallback (in order):
1. **Trakt API** (`/shows/{slug}/watchnow/au`) - most reliable
2. **JustWatch by TMDB ID** - backup
3. **JustWatch by title** - final fallback

## Rating System

Each show has a simple rating structure:

| Field | Purpose | AI Use |
|-------|---------|--------|
| `watchPreference` | "solo" or "together" | Filters recommendations by context |
| `watchPreferenceNote` | WHY this preference | Learns context patterns |
| `rating` | 0.5-5 stars | Weights show importance |
| `reviewNote` | What you liked/disliked, or why you dropped | Learns taste preferences |
| `notes` | General notes | Not used for AI |

### Show Data Format

```json
{
  "id": 1,
  "tmdbId": 12345,
  "title": "Show Name",
  "year": 2024,
  "posterPath": "/abc.jpg",
  "overview": "...",
  "genres": ["Drama", "Thriller"],
  "numberOfSeasons": 4,
  "showStatus": "Ended",
  "watchPreference": "solo",
  "watchPreferenceNote": "Too intense for watching together",
  "rating": 4.5,
  "ratedAt": "2026-01-11T10:00:00Z",
  "reviewNote": "Incredible tension, amazing character arc",
  "notes": "General notes",
  "predictedRating": 4.0,
  "predictedRatingReason": "Predicted 4★: [detailed 400-600 char reasoning]",
  "recommendedWatchPreference": "solo",
  "predictionsUpdatedAt": "2026-01-11T10:00:00Z",
  "hidden": false,
  "dropped": false,
  "imdbRating": 8.5,
  "rtCriticsScore": 95,
  "rtAudienceScore": 88,
  "streamingServices": ["netflix", "stan"]
}
```

**Note on `dropped`:** Shows with `dropped: true` are hidden from all views but kept in the data for taste analysis.

## Generating Recommendations

### Two Types

1. **Predictions** - Rating predictions for ALL shows regardless of subscription status
   - Stored in `shows` table (`predictedRating`, `predictedRatingReason`)
   - Do NOT mention platform names in prediction reasons

2. **Recommendations** - Curated picks for SUBSCRIBED services only
   - The "what to watch now" list
   - Can mention platform names

### Workflow

1. Query shows data from database to understand viewing history and preferences
2. Check subscribed services from `streamingServices` table
3. For predictions: Update prediction fields in `shows` table via `/api/shows`
4. For recommendations: Generate curated list based on subscribed services

### Prediction Fields

```json
{
  "tmdbId": 12345,
  "predictedRating": 4,
  "predictedRatingReason": "Predicted 4★: [detailed 400-600 char reasoning]",
  "recommendedWatchPreference": "solo",
  "predictionsUpdatedAt": "2026-01-11T10:00:00Z"
}
```

### Recommendation Format

```json
{
  "generatedAt": "ISO date string",
  "subscribedServices": ["service-slugs"],
  "solo": [
    {
      "title": "Show Name",
      "year": 2024,
      "tmdbId": 12345,
      "posterPath": "/abc123.jpg",
      "reason": "Why they'd like it",
      "streamingServices": ["service-slug"],
      "confidence": "high" | "medium" | "low"
    }
  ],
  "together": []
}
```

Include `tmdbId` and `posterPath` when possible so poster images display.

### Service Slugs

`netflix`, `stan`, `binge`, `disney-plus`, `prime-video`, `paramount-plus`, `apple-tv-plus`, `max`, `foxtel-now`, `britbox`, `abc-iview`, `sbs-on-demand`, `ten-play`

### Current Subscriptions

Check `streamingServices` table. As of last update: Stan, Prime Video, Max, ABC iview, SBS On Demand.

### Guidelines

**What NOT to recommend:**
- Shows with status "completed" (no rewatches unless explicitly asked)
- Shows with status "dropped" (already decided against these)

**OK to recommend:**
- Shows from the watchlist - prioritize these
- Shows with status "watching" - can remind about these
- New shows not in the library

**Rating weight for taste matching:**
- 5★ = All-time favorite | 4-4.5★ = Strong signal | 3-3.5★ = General patterns | 2-2.5★ = What to avoid
